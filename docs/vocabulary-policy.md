# Open vocabulary policy

**Open Vocabulary, Natural Evolution.**

Full English words are always accepted. Users can try abbreviations, provide the full form for unfamiliar readers and propose entries. The lexicon records evidence and decisions for the uses it describes.

## Sources in preference order

1. Familiar English base words.
2. Existing Internet abbreviations.
3. Existing common English short forms.
4. Useful principles from English shorthand.
5. Experimental WOLN abbreviations.
6. International words that demonstrably improve accessibility.

## Review stages

| Status | Meaning |
| --- | --- |
| PROPOSED | A documented suggestion with a full English equivalent and examples. |
| CANDIDATE | A form selected for review and testing. |
| COMMON | Evidence shows repeated real-world use and understanding for a stated audience and meaning. |
| RECOMMENDED | Review supports use in a stated context, with evidence and collision notes. |

An abbreviation's existing English usage is recorded separately from its WOLN review status. A form can remain a WOLN candidate even when some English users already use it. No experimental form advances based on an AI guess or a single example.

The [starter lexicon](../lexicon/core-words.csv) preserves the initial entries. The [candidate table](../lexicon/short-words-candidates.csv) records source class, examples, status and ambiguity. `CMPSTN` and `ALYZ` are experimental proposals. Use `compare` as a familiar full form. `cmp` has several plausible expansions. Use `yday` or `yesterday` for yesterday. `YTD` can mean year to date.

A proposal should include the full form, intended meaning, an example, evidence if available, audiences and plausible collisions. On ambiguity, keep the original token, state possible readings and ask for clarification when the decision changes the message. Use a full form whenever it helps the reader.
